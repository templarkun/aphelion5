# APHELION 5 - CAMPAIGN 1 DATABASE (structured, machine-oriented)
# Rules semantics live in "Core Rules.txt" (7.2 Mission Preparation, 7.3 Allied Drop,
# 8.2 Mission objectives, 5.6 Orders). Unit stats live in "unit_list_structured.txt".
# This file stores the Campaign board (Omega units, campaign Orders) and the missions.
################################################################################

=== FORMAT SPEC ===
1. The file has SECTIONS. Each section starts with "=== SECTION: <name> ===".
2. Each entry is a RECORD: a block of "key: value" lines, one key per line, records
   separated by one blank line. A record always begins with "id:". Keys never repeat.
3. Absent key = not applicable. "none" is written only where absence is meaningful.
4. Multi-step effects are numbered inline: "[1] ... [2] ...". Execute in order.
5. Effect text uses Core Rules terminology. Do not reinterpret.
6. Tile lists. "ID xN" = N copies of tile ID (shuffled into the mission deck; Core Rules 7.2,
   step 2). A Threat column lists each tile individually (a repeated ID = several copies).
   "G_00" = take one tile from the top of the Energy deck without looking (Core Rules 4.3).
7. Omega placement. "omega_placed" lists Omega unit types that are NOT shuffled in: one such
   tile is placed face up on each sector listed under "omega_sectors" (Core Rules 7.2,
   step 2). Sectors holding an Omega unit receive no tiles when the mission deck is dealt
   (Core Rules 7.2, step 5).
8. Mission map coordinates: axial (q, r), as defined in Core Rules 3.8. (0,0) is the
   starting sector. r + 1 = one step right; q + 1 = one step up-right. A horizontal row is
   every map sector with the same q. Each sector is written "(q, r)".
9. Objectives (Core Rules 8.2): objective_type "salvage" = at least 5 Power Nodes in the
   Trophy pile and at least 3 Cleared sectors. objective_type "eliminate" = at least
   objective_count units of type objective_target in the Trophy pile.
10. Mission events (event_type): allied_drop (event_level = Level; Core Rules 7.3) |
    gain_energy (event_amount; colours of your choice, Core Rules 5.4) |
    take_module_top (take one Module from the top of the Module deck) | none.
11. Alternative routes: missions sharing a number (2x/2y, 4x/4y) are alternatives; choose
    one, the other is skipped for this campaign (Core Rules 7.2, step 1).
12. Orders: Core Rules 5.6. "[Overload]" = usable only during an Overload.

KEY ORDER (MISSION):
  id, number, route, deployment_shuffled, omega_placed, omega_sectors,
  threat_A, threat_B, threat_C, threat_D, objective_type, objective_target,
  objective_count, event_type, event_level, event_amount, map_sector_count, map, orders
