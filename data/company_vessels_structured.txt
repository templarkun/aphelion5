################################################################################
# APHELION 5 - COMPANY DATABASE (structured, machine-oriented)
# Unit stats AND Mecha base abilities live only in the Unit database
# (unit_list_structured.txt). This file stores Company-specific data: starting
# Mecha counts, Flagship, Trait and upgrades. Rules semantics live in "Core Rules.txt".
################################################################################

=== FORMAT SPEC ===
1. One COMPANY block per Company, starting with "=== COMPANY: <company_id> ===".
2. Inside a Company, data is split into named PARTS ("--- PART: <name> ---").
3. A part is either:
   - FIELDS: "key: value" lines (single record), or
   - RECORDS: blocks of "key: value" lines separated by one blank line; each starts with "id:".
4. Key order inside a record is fixed (see each part). One key per line, no repeats.
5. Effect text uses Core Rules terminology. V1_M04_U2, U2A and U2B were reworded for clarity.
6. Ability tags (Core Rules 4.2):
   Command:       optional; use it when you Command this Mecha in the Command phase.
   Expend:        as Command, then destroy this Mecha.
   Passive:       always on; modifies how the Mecha moves or attacks.
   [Overload]     prefix; usable only during an Overload (never in the Command phase).
   At Overload:   mandatory trigger; Alert token at the start of every Overload.
   Bay abilities without [Overload] are used in the Command phase.
7. Upgrade vocabulary:
   cost          = number of upgrade slots that must be marked to fully fill the upgrade
                   (1 Upgrade point marks 1 slot; Core Rules 10.2).
   state         = "available" (can be filled from the start) or "locked" (cannot be filled
                   until the upgrade named in unlocked_by is fully filled).
   unlocks       = ids that become available when THIS upgrade is fully filled.
   unlock_mode   = "all"        -> every listed id becomes available
                   "choose_one" -> all listed ids become available, but they are mutually
                                   exclusive (see exclusive_with)
   exclusive_with= ids that can never be filled once this upgrade has received its first
                   marked slot, until the sheet is erased for a Fresh campaign (Core Rules 7.1).
   effect        = the new ability. It is a new option: whenever you use that Mecha or Bay,
                   choose any one of its abilities, original or upgraded (Core Rules 10.2).
                   "Improves X" upgrades simply modify ability X.
   kind          = "permanent_ability" or "requisition" (one-time effect when fully filled;
                   "repeatable: yes" means erase its slots afterwards so it can be filled again).
8. "applies_to" lists Mecha unit ids (from the Unit database) or "all_mecha" / "flagship_bay_N".
9. Starting Mecha: unit id + count only. Levels and base abilities are in the Unit database.
10. TRAIT: a Company Trait is a special rule that is always in effect (Core Rules 5.1).
    It states its own timing. "none" = this Company has no Trait.
11. ALLY: each printed sheet has an "Ally" field. At the first Allied Drop of a campaign,
    write the name of one other Company there; all Allied Drops that campaign come from it.
    Erase it at Game End (Core Rules 7.3, 10.3).
12. Effects that remove Alert tokens name the units they work on, and never work on Flares
    or Wrecks (Core Rules 6.5).
