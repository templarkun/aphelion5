# APHELION 5 - MODULE DATABASE (structured, machine-oriented)
# Rules semantics live in "Core Rules.txt" (5.3 Modules, 8.6 Run a Module, 9.2 Overloads).
# This file only stores Module data and the text conventions that apply to Module effects.
################################################################################

=== FORMAT SPEC ===
1. The file has SECTIONS (one per energy colour). Each section starts with a line
   "=== SECTION: <name> ===" and has a SECTION_DEFAULTS block.
2. A Module inherits every default unless the record sets the same key itself
   (record value wins).
3. Each Module is a RECORD: a block of "key: value" lines, one key per line, records
   separated by one blank line. A record always begins with "id:". Keys never repeat.
4. Absent key = not applicable.
5. Multi-step effects are numbered inline: "[1] ... [2] ...". Execute in order unless the
   text says otherwise.
6. Effect text uses Core Rules terminology (Boost, Bury, Reveal, Drain, Destroy, Dark sector,
   Cleared sector, Horizontal row, Tick, Barrier, Overload, etc.). Do not reinterpret.

KEY ORDER:
  id, name, cost, cost_variable, cost_reduction, effect, extra_payment

KEY DEFINITIONS:
  id              Unique Module ID (integer).
  name            Final Module name.
  cost            Base cost, in the section's energy colour. "X" = variable cost (see cost_variable).
  cost_variable   Explains X, or the extra payment that is part of the cost itself.
  cost_reduction  Discount applied when you pay (Convention 5). A cost never drops below 0.
  effect          What the Module does when run (Core Rules 8.6, step 3).
  extra_payment   Optional. An additional payment, made while resolving the effect, for a bigger
                  effect. You may pay it or skip that part (Core Rules 8.6, step 3).

SECTION-LEVEL FIELDS (inherited by every Module in the section):
  energy_color    Colour of the Module's cost.
  background      light = run only in the Command phase; red = run only during an Overload
                  (Core Rules 5.3).

DISTRIBUTION: one copy of each Module, 78 cards: 26 Yellow (IDs 1-25, 77), 26 Red (IDs 26-50, 78),
26 Blue (IDs 51-76).

--------------------------------------------------------------------------------
MODULE TEXT CONVENTIONS (apply to every Module unless its text says otherwise)
--------------------------------------------------------------------------------
1. Targets. "A unit" / "one unit" means any unit on the Field that can be chosen. When one
   effect names several targets ("one unit ... one Gyro ... one Sleeper"), each must be a
   different unit.
2. "Adjacent to it" after damage is measured from that unit's sector, even if the
   damage destroyed it.
3. Counts ("for each Bot", "exactly three", "the fewest", "the most") use the units on
   the Field when the effect starts. Wrecks and Flares count (Core Rules 4.6, 4.8). Ties: you
   choose (Core Rules 11.1, rule 2).
4. "Deal X damage to one unit" is a single hit of X (Core Rules 6.1). Bonus damage that an
   effect adds before dealing it is part of the same hit.
5. Cost reductions are counted when you pay. A cost never drops below 0. "Your other
   exhausted Modules" never counts the Module being run.
6. "Place energy on a Module" = take it from the Supply and put it on a ready Module
   (Core Rules 5.3). If no colour is named, you choose the colours. "Return energy" =
   put it back in the Supply. The Module being run is not ready while it resolves, so
   energy is never placed on it (Core Rules 8.6).
7. Flares and Wrecks can never be chosen (Core Rules 4.6, 4.8). They never gain or lose
   tokens except their own Alert, and effects that hit or Boost "all" units skip them.
8. Effects that remove Alert tokens name the units they work on; they never work on
   Flares or Wrecks (Core Rules 6.5).
9. An effect that runs another Module for free still follows the background rule:
   light in the Command phase, red during an Overload (Core Rules 5.3).
